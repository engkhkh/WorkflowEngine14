## Doc deviations
- U5-02 duplicate: the doc says registering Mona twice (same date of birth) is "warned about". The API only detects duplicates by NATIONAL ID (409 "This national id is already registered (MRN-000001)"). A second "Mona Saleh" with same DOB but no national id would be created silently. The script registers the three patients with national ids and tests the duplicate with the same id; the name+DOB case is NOT tested (it would create a 4th file and shift the numbers).
- U5-01 "bed charge 350 per night" is the daily rate of the ward W1 (there is no bed-charge service). "Consultation fee 200" is set on the doctor (fee) and as service CONSULT. Doctor hours are set 09:00-13:00 (doc gives only the start).
- U5-01 lab test GLU: doc gives 70-100; critical limits are not in the doc, script uses critLow 50 / critHigh 400 so that 450 is "Critical high".
- U5-03 appointments are booked 4 days after the run date (server refuses bookings in the past), not 2026-10-12.
- U5-05 the warning is HTTP 409 with `warnings[]` and a reason of at least 5 characters is required.
- U5-06 the first dispense without `allowPartial` is refused (409 shortage); the Partial 10/15 comes from `allowPartial:true` (what the portal's confirm box sends).
- U5-08 the discharge summary is stored on the ADMISSION record (`summary`), not on the visit. Discharge time is the server's "now" (no date can be sent), so the bed charge is 1 day = 350 as long as discharge happens within 24 h of admit. The pharmacy must also dispense METF 60 (script does it inside U5-08) because invoices bill dispensed quantity only: 60 x 0.40 = 24.
- U5-09/10: no tax is configured (taxPct 0), so invoices are 268.00 and 624.00 as in the doc.
- U5-11 overview: the dashboard has no "billed" or "collected" fields. Script computes billed 892 and collected 568 from the invoice list, and checks dashboard `revenueToday` 568 and `outstanding` 324. "Admissions 1": the dashboard `admitted` counts people CURRENTLY admitted = 0 after discharge; script asserts 0 and that there is 1 admission record. Bed occupancy back to 0 of 6 is asserted.
- U5-12 org chart: there is no org-chart endpoint; the chart is built in the browser from `managerEmpNo`. Script verifies Sara has no manager and four employees point to E001. The CSV import is client side in the portal; the script builds the same CSV, maps columns and posts to /employees/import. A leave type ANNUAL with 21 days is created here (the doc assumes the balance 21).
- U5-13 GOSI: payroll elements only support "fixed" or "% of basic". "9.75% of basic + housing" is therefore entered as 12.1875% of basic (= 9.75% x 1.25). Result identical (e.g. 18,000 -> 2,193.75; Reem 1,828.125 rounds to 1,828.13).
- U5-14 / U5-14b: hiring does not "keep Hanan out of the October run". The calculation pays EVERY non-terminated employee of the run's company and ignores `hireDate`. U5-14b therefore FAILS (reported as a defect). So that Noura's figures (net 112,759.37) hold, U5-17 temporarily moves Hanan to another company code (`NOT-STARTED`) before recalculating the run, then restores her company. If this defect is fixed, the workaround is skipped automatically. Without the workaround the run would be 6 people: gross 136,000.00 (incl. bonus), GOSI 12,187.51, net 123,812.49... (Hanan: gross 12,150.00, GOSI 1,096.88, net 11,053.12).
- U5-15 balance (21 -> 18) is not stored: it is computed from approved leave records (as the portal does). "Shows on HR calendar" is UI only.
- U5-17 there is NO "submit" action. Actions are calculate / approve / post. The run stays `Calculated` which is the state Noura sees as waiting for approval. Run gross = 123,850.00 (the doc's gross column 122,850 plus the 1,000 bonus, which is an earning on Faisal's slip); deductions 11,090.63; net 112,759.37. The slip gross of Faisal is 22,600.
- U5-17 period is the fixed string `2026-10` (only a label). Noura's post later drafts a journal dated with the server's today.
