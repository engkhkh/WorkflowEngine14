## Doc deviations (document says -> real API -> expected figure used)

- U4-01 VAT: document shows prices without VAT and adds 15% on top (56.00 + 8.40). POS default is "prices include tax". u4 sets POS setting `pricesIncludeTax=false` so the document's figures hold. Payment methods Cash/Card are fixed in the product (no setup record).
- U4-01 stock: POS stock is the shared ledger keyed by branch code (Faisal's day-2 transfer must land in branch DMM). If the shop has less than 40/20/10/10 on day 3, u4 tops up with stock/adjust (reason noted in the step) so the sale figures can still be checked; if stock was already exact the final 38/20/8/9 is asserted absolutely, otherwise by delta.
- U4-02 "Disqualified": the lead status is `Unqualified`; the reason ("Budget too small") is stored in lead data (`reason`).
- U4-03 stage probability: "Proposal 50% / Negotiation 75% set in CRM setup" does not exist; CRM setup only has stage names, sources, tax. Probabilities are per opportunity (data.probability, UI fills them from a fixed table). u4 writes 50 and 75 on the opportunities. Weighted = sum(amount x probability) of Open opportunities = 105,000 (as in the document).
- U4-04 "meeting also in Reem's calendar": a CRM activity does not create a calendar entry. u4 books a separate calendar event (14:00 Riyadh = 11:00 UTC) and checks it in the calendar list.
- U4-05 "Both opportunities move to Won": accepting a quote does not move the opportunity. u4 calls opportunities/{id}/won, which also creates a finance customer (code = CRM account code) when the caller has finance.ar.manage.
- U4-06 Sales documents: there is no quote -> order -> delivery -> invoice chain. Sales orders are the workflow "ERP Sales Order (Order-to-Cash)" (api/instances/start, needs sales.create). The flow then waits at "Credit Check" (role finance); "Deliver Goods" is assigned to role admin-stores and "Invoice & Collect Payment" to finance; the final GL step only logs. Nothing reaches Faisal's pick list automatically (picks are manual `wh/pick` records) and no receivable invoice is created by the flow. u4 starts the two order instances (Q-1001 17,250; Q-1002 14,490) and creates two DRAFT receivable invoices through api/finance/records/arinvoice (Reem has finance.ar.manage) with the same totals, so Noura finds them in receivables as Draft (she must issue them). Customer = Noura's customer from ctx.S.customers when its name matches, else a finance customer with that name, else the CRM account code. Net/VAT: Q-1001 15,000 + 2,250; Q-1002 12,600 + 1,890. Terms: Al-Hayat 60 days, Najd 30 days.
- U4-07 Campaign "to the three contacts": the campaign record has no recipient list or send engine (fields: name, type, dates, budget, spent). u4 stores `recipients` in the campaign data. Only two contacts come from converted leads, so u4 adds Bayan Dental Center as a third contact by hand to reach 3. Budget 2000, spent 0.
- U4-10 receipt subtotal: API `subtotal` is before discount = 93.00, `discount` 6.80; the document's 86.20 is subtotal less discount. VAT 12.93 and total 99.13 match.
- U4-12 Z-report: there is no separate Z-report endpoint; the figures come from the closed shift record (salesTotal 163.53, returnsTotal 29.90, salesTax 21.33, returnsTax 3.90, cashSales 64.40 (70.00 tendered less 5.60 change), refundCash 29.90, cardSales 99.13). Net 116.20 + VAT 17.43 = 133.63; cash 34.50. Expected cash 534.50, variance -4.50.
- U4-13 budget is the sum of the budget lines (Labor 30,000 + Material 40,000 + Other 10,000 = 80,000); billing model set to `milestone`; allocation rates set as costRate = billRate (200 / 150).
- U4-14 timesheets for Faisal are entered by Reem (Faisal has no prj.time.log); `employee` = Faisal's username. Cost = hours x costRate: 2,400 + 1,600 = 4,000, + 5,500 materials = 9,500 = 11.9% of 80,000.
- U4-15 billing: a milestone must be set to Achieved first (u4 does this); the invoice is a DRAFT receivable (not issued), customer = project customer.
- U4-16 website order: the API total is the sum of price x qty without VAT (130.00); 19.50 VAT / 149.50 are computed on screen, not stored. Statuses are new / confirmed / shipped / done / cancelled, so "Processed" = `done`. The order is posted by u1 if it exists (name contains Bayan), otherwise by u4 with sku GLV-NIT-M x 5; the site's published price list must contain GLV-NIT-M at 26.00 or the post is refused ("A product in the cart is not available").
- U4-17 custom module: Reem has cus.view + cus.manage only; creating/changing a module needs cus.design (see below). The assistant commands are browser-only (manual U4-17-UI); the API step runs the same three calls the assistant makes. Template fields: Visitor name (required, first field), Company, Phone, Host, Visit date, Purpose, Status (Expected/In/Out). The document's "Dr. Majed ... Contract review" row therefore uses Visitor name / Company / Host / Visit date / Purpose.
- U4-19 `.ics` times are UTC: 14:00 Riyadh appears as DTSTART:20261014T110000Z. Invitation e-mail is only sent when a mail server is configured.
